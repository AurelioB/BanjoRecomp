## Build commands

Default runtime APK:

```bash
source ~/.config/android-build-env.sh
export PATH=$(printf '%s' "$PATH" | tr ':' '\n' | grep -v 'toolchains/llvm/prebuilt/linux-x86_64/bin' | paste -sd: -)
export PATH="/usr/lib/llvm-19/bin:$PATH"
gradle -p android --no-daemon :app:assembleDebug
```

Install and launch:

```bash
adb install -r android/app/build/outputs/apk/debug/app-debug.apk
adb shell am start -n com.aure.banjorecomp/io.github.banjorecomp.BanjoSDLActivity
```

Probe mode is opt-in with `-PbanjoProbe=true`; it still launches through `BanjoSDLActivity` and builds an SDL lifecycle `libmain.so`. The retired text-view `MainActivity`/`BanjoAndroidShell` path is no longer a supported Gradle mode.

Run guard checks:

```bash
python3 tools/check_android_port_guards.py
```

When inspecting performance or CPU stalls, do not judge Android native performance from an unoptimized Debug/CMake `-O0` build. Verify `compile_commands.json` or Gradle/CMake args include an optimization override such as `-O2`/`-O3`, or build a release/RelWithDebInfo-style variant.

## Dev-full APK and legal/artifact hygiene

- The dev-full flavor can package ROM-derived generated assets for local testing only. Treat it as local-only and not distributable.
- Do not commit ROMs, decompressed ROMs, generated ROM-derived C/C++ outputs, APKs, Gradle/CMake build products, `.cxx`, `.gradle`, `__pycache__`, or other generated artifacts unless the user explicitly approves and project policy allows it.
- Keep generated files and Android build outputs ignored or cleaned before commit/PR review.

## Android lifecycle/rendering constraints

- Use SDLActivity/SDL Java glue for real Android lifecycle testing. A raw native executable launched through `adb shell` is only a linker/startup smoke test.
- Android recents/task switching can trigger focus loss before pause. Treat focus loss as app-inactive for gameplay and queued audio.
- If audio static or repeated `AudioTrack: stop(...)` appears after resume, inspect Android SDL queued-audio handling before blaming rendering.
- For SDL/Vulkan surface recreation, destroy the old swapchain/surface before creating a replacement `VkSurfaceKHR`. Android/SDL can crash if two active SurfaceView BufferQueue connections exist. If recreation fails, leave handles null and retry on the next surface/resize event.
- Do not create a second SDL-created Vulkan surface while the old one is still alive.
- For black-screen debugging, prove layers in order: Java/SurfaceView output, SDL renderer output, minimal swapchain clear, then engine/RT64 path.

3. Classify changes by subsystem: Gradle/Android app shell, CMake, SDL lifecycle, audio, renderer/swapchain, storage paths, generated assets, and docs.
